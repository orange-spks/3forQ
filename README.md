# 3for - 一次提问，多源搜寻

> **问一次，多种不同类型的信息源同时呈现结果，AI 一句话总结。**

## 核心洞察

现在市面上所有"多 bot 对比"工具都犯了同一个错误：
> 让你同时问 10 个差不多的 LLM，得到 10 份差不多的回答。

真正有价值的是：
> **一次输入，多种完全不同类型的信息源**，获得互补的、全方位的信息！

## 可用信息源

| 信息源 | 类型 | 独特价值 |
|--------|------|----------|
| ChatGPT | LLM | 最强通用推理、逻辑分析、复杂问题拆解 |
| 豆包 Doubao | LLM | 响应最快、中文优化、关联视频教程 |
| 小红书 Xiaohongshu | 社区 | 真实用户体验、种草避坑、生活决策参考 |
| Kimi | LLM/搜索 | 长文本处理、深度分析、研究导向 |
| 秘塔搜索 Metaso | AI搜索 | 学术搜索、知识图谱、结构化知识检索 |
| 必应搜索 Bing | 搜索引擎 | 广泛网页覆盖、实时新闻资讯、多语言结果 |
| Gemini | LLM | Google 多模态 AI、实时联网搜索、长上下文理解 |
| Grok | LLM | xAI 实时搜索、长推理、少过滤响应 |

默认展示 4 个面板（ChatGPT、Doubao、Xiaohongshu、Kimi），可通过面板头部的切换按钮自由替换为任意可用信息源。

```

└──┬──────┬──────┬──────┬─────┘
   │      │      │      │
   ▼      ▼      ▼      ▼
┌──────┐┌──────┐┌──────┐┌──────┐
│源 1  ││源 2  ││源 3  ││源 4  │  ← 嵌入式 webview
└──────┘└──────┘└──────┘└──────┘     （可自由切换信息源）
   │      │      │      │
   └──────┴──┬───┴──────┘
             │  内容提取
             ▼
      ┌─────────────┐

      └──────┬──────┘

      │  答案总结面板  │  ← 综合结论 + 各来源亮点
      └─────────────┘
```

### 工作原理

1. **浏览器模拟**：每个数据源以 Electron `<webview>` 形式嵌入，加载真实网站页面（非 API 调用）。
2. **统一搜索**：顶部搜索框将查询广播到全部数据源。
3. **自动填充 & 提交**：JavaScript 注入到每个 webview 中，自动找到搜索输入框、填充查询内容、并触发搜索。
4. **答案总结**：搜索完成后，点击底部"答案总结"按钮，应用从各 webview 提取回答内容，通过可配置 LLM API 生成综合总结。
5. **信息源切换**：点击面板头部的切换按钮，可从 8 个可用信息源中选择替换当前面板。
6. **面板全屏**：点击面板头部的展开按钮，可将单个面板放大至全屏查看。
7. **面板级缩放**：使用 `Ctrl/Cmd + Plus/Minus/0` 快捷键缩放当前鼠标悬停或聚焦的面板；未命中面板时，回退到同时缩放所有面板。
8. **外部链接阅读器**：在任意 webview 中点击外部链接，会打开独立的 3for Reader 多标签窗口，支持复制链接、浏览器打开、页面内查找。
9. **一键新建对话**：点击顶部工具栏的"为所有 LLM 新建对话"按钮，可同时为所有 LLM 源触发新建对话。
10. **会话持久化**：登录状态在应用重启后自动保留（通过 Electron `persist:sources` 分区）。登录一次，永久使用。

### 为什么选择浏览器模拟？

- **无需 API Key** — 使用你已有账号的真实网站
- **真实结果** — 看到的和正常浏览器打开完全一致
- **完整功能** — 所有网站功能正常运作（排版、链接、图片等）
- **无调用限制** — 仅受各网站正常使用策略约束

## 快速开始

### 环境要求

- **Node.js** >= 18
- **npm** >= 9
- **LLM API Key** — 支持 DeepSeek、通义千问、Kimi/Moonshot、硅基流动、OpenAI 等任何 OpenAI 兼容 API

### 安装和运行

```bash
# 安装依赖
npm install

# 启动应用
npm start

# 启动并打开开发者工具（调试用）
npm run dev
```

### 首次使用设置

1. 应用启动后，4 个数据源面板会各自加载对应网站。
2. 在每个面板中 **登录你的账号**（点击面板，正常登录即可）。
3. 登录状态会 **自动保存** — 下次启动不需要重新登录。
4. 点击右上角 **⚙ 设置按钮**，配置 LLM 供应商（Base URL + API Key + 模型名称），或使用快捷预设按钮选择 DeepSeek/千问/Kimi 等。
5. 在顶部搜索框输入问题，按 **Enter** — 所有数据源将同时搜索。
6. 等待搜索结果加载后，点击底部 **"答案总结"** 栏展开面板，点击 **"生成总结"** — AI 将综合所有来源给出结论。

### 快捷键

| 快捷键 | 功能 |
|--------|------|
| `Enter`（搜索框内） | 广播搜索到所有数据源 |
| `Ctrl/Cmd + L` | 聚焦搜索框 |
| `Ctrl/Cmd + R` | 刷新所有数据源面板 |
| `Ctrl/Cmd + +` | 放大当前悬停/聚焦的面板（未命中面板则缩放全部） |
| `Ctrl/Cmd + -` | 缩小当前悬停/聚焦的面板（未命中面板则缩放全部） |
| `Ctrl/Cmd + 0` | 重置当前悬停/聚焦的面板缩放（未命中面板则重置全部） |
| `Escape` | 取消搜索框焦点 / 关闭信息源选择器 / 退出全屏面板 |

## 功能详解

### 信息源切换

每个面板头部有一个 **切换按钮**（箭头图标），点击后弹出信息源选择器：

- 显示所有 7 个可用信息源及其类型和独特价值描述
- 当前面板标记为 "Current"
- 已被其他面板使用的信息源半透明显示，但仍可选择（允许重复）
- 选择后当前面板立即切换为新信息源，自动加载对应网站

### 面板全屏展开

每个面板头部有一个 **展开按钮**（四角箭头图标），点击后：

- 面板放大至覆盖整个网格区域，带紫色边框高亮
- 按钮图标变为收起箭头
- 再次点击或按 `Escape` 可退出全屏

### 面板级缩放

使用 `Ctrl/Cmd + Plus` 放大、`Ctrl/Cmd + Minus` 缩小、`Ctrl/Cmd + 0` 重置。默认缩放当前鼠标悬停或键盘聚焦的面板；如果没有任何面板被瞄准，则同时应用到所有 webview 面板。每个面板的缩放档位独立保存，右上角短暂显示当前缩放百分比。

### 答案总结

答案总结功能通过可配置的 LLM 综合分析所有信息源的回答内容，输出结构化的总结。支持随时重新生成。

**流程：**

1. **内容提取** — 通过 `webview.executeJavaScript()` 注入提取脚本，采用三级回退策略：
   - 选择器匹配（如 `[data-message-author-role="assistant"]`、`.markdown-body`、`[class*="answer"]`、`model-response` 等）
   - 最大文本块检测（找页面上最可能是回答的 DOM 元素）
   - Body 尾部回退（取页面文本最后 5000 字符）
2. **Prompt 构建** — 将提取到的内容按信息源组织，附带每个来源的类型和独特价值描述
3. **API 调用** — 渲染进程通过 IPC 发送到主进程，主进程调用用户配置的 LLM API
4. **结果解析** — 正则解析 LLM 输出，渲染为综合结论 + 各来源亮点卡片

**常驻重新生成：**
- 总结结果生成后，底部触发栏和结果区域均显示 **"重新生成"** 按钮
- 支持随时重新生成总结（如信息源更新了内容）

**Prompt 设计：**

- **System Prompt**：定义角色为"多源信息综合分析助手"，强调结论必须综合所有信息源（非依赖单一来源），亮点需突出各来源的独特价值（如 LLM 的深度推理、社区的真实体验、搜索引擎的广泛覆盖）
- **User Prompt**：动态拼接用户问题 + 各来源内容及格式指令，根据当前活跃的信息源自动调整输出格式要求
- 每个来源内容截取最多 5000 字符，temperature 设为 0.7，max_tokens 1500

**架构选择：**

- API 调用放在 **主进程**（main.js），避免在渲染进程暴露 API Key
- 通过 `contextBridge` + `ipcMain.handle` 安全通信，渲染进程不接触 Node.js API
- 请求超时 120 秒，含完整的错误处理和重试机制

### LLM 供应商配置

点击右上角 ⚙ 设置按钮打开 LLM 配置面板，支持任何 OpenAI 兼容 API 格式：

- **DeepSeek**：`https://api.deepseek.com/chat/completions` / `deepseek-chat`
- **通义千问**：`https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` / `qwen-turbo`
- **Kimi/Moonshot**：`https://api.moonshot.cn/v1/chat/completions` / `moonshot-v1-8k`
- **硅基流动**：`https://api.siliconflow.cn/v1/chat/completions` / `deepseek-ai/DeepSeek-V4-Flash`
- **OpenAI**：`https://api.openai.com/v1/chat/completions` / `gpt-4o`

用户只需填写 Base URL、API Key 和模型名称即可。设置保存在 `llm-config.json` 文件中。旧版 `deepseek-api` 文件仍然兼容（自动迁移），建议新用户直接使用设置面板配置。

### 自动填充机制

在顶部搜索框按 Enter 后，应用会：

1. 对每个面板调用 `webview.executeJavaScript()`
2. 注入的脚本根据源类型选择策略：
   - **Grok**：优先通过特征选择器（`placeholder`、`aria-label`）命中真正的 prompt 输入框，避免误填「搜索已有对话」
   - **其他 LLM 源**：使用 `textarea` / `contenteditable` / `div[role="textbox"]` / `input[type="text"]` 等选择器，排除搜索框后优先选择页面中下部最靠下的输入框
   - **非 LLM 源**：使用包含 `input[type="search"]` 的选择器，取第一个可见输入框
3. 使用 React 兼容的 value setter 填充内容（触发 `input`/`change`/`compositionend` 等事件）
4. 尝试点击发送/提交按钮（多种选择器策略，包括搜索输入框附近的按钮）
5. 若按钮未找到，回退到触发 Enter 按键事件（keydown + keyup）
6. 自动重试最多 3 次（间隔 1 秒），适应页面加载延迟

详细定位逻辑可参考 `doc/问题注入逻辑.md`。

### 为什么用 Electron（而不是 Web 应用）？

大部分目标网站（ChatGPT、豆包、小红书、Kimi）设置了 `X-Frame-Options: DENY` 或严格的 CSP 头，阻止在 `<iframe>` 中嵌入。Electron 的 `<webview>` 标签绕过这些限制，同时保留完整的浏览器功能。

### 会话持久化

Webview 使用 `partition="persist:sources"`，将 Cookie、localStorage 和 IndexedDB 保存到磁盘。这意味着：
- 登录一次，跨应用重启持久保存
- 每个数据源维护独立的登录状态
- 无需管理任何 API Key（信息源层面）

## 历史原型

`archive/` 目录包含最初的 Python 原型，用于可行性验证阶段。该方案采用 API 调用（配合 mock 数据回退）。当前版本采用了完全不同的架构：基于 Electron webview 的浏览器模拟。
